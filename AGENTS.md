# tomzlab-web — Repository Instructions

Always read current `uichat-mira/.github/AGENTS.md` and its routed guidance.

## Product and ownership
- `tomzlab.cn` is the individual noncommercial website “党靖涛的记事本”, not a business or paid service. Publicly approved ICP/security registration numbers may be displayed; never commit private filing documents, credentials, addresses, or PII.
- **Folio dev consumer experiment:** Folio owns Header, structured Footer, Pearl theme, search, React routes, Markdown rendering, canonical metadata, sitemap, 404 and static output. The consumer customizes **only the homepage body** (`slots.home`) and brand (`slots.headerBrand`) using public interfaces. Do not re-create Folio page shells.
- All other main sections use Folio `type: page` documents in `folio-site/content/`. `projects.md` and `about.md` are grounded in `prod@6a34c9fc`; generated `notes/index.md` and `weekly/index.md` are **build-time data projections** of the two external publishers' RSS. Preserve their ownership; no copied articles or fabricated posts.
- Former `notes.html`, `weekly.html`, `projects.html`, `about.html` URLs are **noindex redirect aliases only**, generated by `write-legacy-redirects.mjs`. The old hand-built HTML/CSS/JS content pages are retired. Folio is the single route and rendering source of truth.
- Feed failures must be visible: generator logs source errors and writes a labeled dated offline snapshot. Never claim a fallback is fresh or silently convert unavailable feeds into fabricated posts.

## Engineering and publishing
- Pinned Folio `dev@36547bd4818d63268ae5e9d88f79e34861642e87` is a **test-only tarball overlay** until reviewed and published to npm. Do not confuse `npm ci` with dev integration, and do not publish from this candidate to production.
- `feat/* → dev → test → prod`; main remains bootstrap. Test with `npm run typecheck && npm run build && python3 scripts/check_site.py`. Exercise browser routes, search, navigation, mobile menu, external article links, fallback and Pages base.
- Current Folio dev static route writer generates no-JS **document bodies** but not complete Header/Footer for non-home routes. This is a confirmed upstream acceptance gap, not permission to paste a second consumer page shell into static HTML. Address it in Folio if full no-JS shell parity becomes a requirement.
- `mira-cloud-infra` still has a fixed raw-file deployment allowlist. Before promoting to prod, independently update and verify its release workflow to publish only the pinned site's verified `_site/` output with existing rollback. No production DNS, certificates, or services are changed by this experiment.
